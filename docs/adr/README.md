# Architecture Decision Records

ADRs registram decisões arquiteturais reais — não decisões triviais ou óbvias a partir do roadmap.

Use um ADR quando houver uma escolha entre alternativas genuínas, com trade-offs, que vai moldar o código por várias versões (ex.: como o domínio se comunicará com a camada de persistência quando o V3 chegar).

Não crie um ADR para decisões já determinadas pelo roadmap em `docs/v1-java-core.md` (ex.: "vamos usar Java puro na V1" não é uma decisão a documentar aqui, é a premissa do projeto).

## Formato

```text
docs/adr/0001-titulo-curto.md

## Status
Proposed | Accepted | Superseded by ADR-000X

## Context
Qual problema motivou esta decisão?

## Decision
O que foi decidido?

## Consequences
O que isso implica, positivo e negativo?
```

Nenhum ADR foi necessário até o momento.
